## Review (26 Oct)

Codex is out of usage until 17 Nov 2026. A code reviewer agent with no build notes read the diff, the spec and design 1, ran `npm test` and its own scripts. It found no path to a ✓ without a run in that hook call. 10 findings, all fixed with a test that failed first:

1. Medium. A lesson file's `author` or `date` could put ✓ on the developer's lesson line. Text from the repo or a teammate now never carries a tick (`noTick()`), and a date is shown only when it is a date. The ⊘ line and the weakened-test line get the same treatment.
2. Medium. File names git quotes (`é.js`, a quote, a backslash) were stored quoted, and with `.codehere/` in a subfolder of the repo the paths were relative to the repo top. Either way the hash was `deleted` and delivery said "unchanged" after a change. Changed files are now read with `-z`, relative to Codehere's folder. This also fixes tamper detection in a subfolder, which missed a skipped test before.
3. Medium. The hash was computed in JavaScript, which differs from `git hash-object` when git filters apply (line endings). It now uses `git hash-object --stdin-paths` with absolute paths, because that option ignores the subfolder git runs in.
4. Medium. After 3 send-backs a solved error wrote no lesson. Now the lesson is written, and the developer is told to fill it in.
5. Medium. python unittest with expected failures gave a wrong pass count. Such output now reads as unknown.
6. Low. A run with exit 0 whose summary shows failures said "N passed". It now says "exit 0".
7. Low. A lesson with proof fields and no author said "verified on undefined's machine". It now needs an author to count as verified.
8. Low. `proof_dirty` could be true when only `.codehere/` changed, because `git()` trimmed the first status line. Fixed by the `-z` read.
9. Low. A real title starting with `<` was treated as unfilled. Only the exact placeholders count now.
10. Low. The ⊘ line was not shown with the lesson request. Every send-back now carries all developer lines.
