## What Codex CLI does (0.159.0)

Every Codex run below used a throwaway repo, its own `CODEX_HOME` and a local model through Ollama (`qwen3.5:9b-q4_K_M`), because the ChatGPT plan's Codex quota is used up until 17 Nov 2026. The developer's own `~/.codex` was not read or changed.

- All four hooks ran with the documented inputs. The inputs are saved in `test/fixtures/payloads/codex-0.159.0.jsonl`, next to Claude Code 2.1.310's in `claude-code-2.1.310.jsonl`.
- A failed command reaches `PostToolUse` as `tool_name: "Bash"`, with the output as plain text and no exit code. Claude Code sends it as `PostToolUseFailure` with an `error` field.
- In the Codex transcript, session-start and post-tool context are developer messages. A Stop block's reason is the next user message (`<hook_prompt …>`).
- Codex skipped untrusted project hooks without any warning in `codex exec`. Trust is kept in the user's `~/.codex/config.toml` (`[hooks.state."<file>:<event>:<i>:<j>"] trusted_hash`). The runs here trusted the hooks through Codex's app-server (`hooks/list`, then `config/batchWrite`). The `--dangerously-bypass-hook-trust` flag was not used.
- `codex exec` printed `hook: Stop Blocked` and similar, never a hook's `systemMessage`. The same is true with `--json`.
- Codex's command tool takes `tty: true`, and `unified_exec_tty` is on by default (`codex features list`). Inside Codex's sandbox, `/bin/ps` fails with `Operation not permitted`. A hook that logged its parent processes showed Codex's process as `codex`, and Claude Code's as `claude`.

## The Codex hooks file removed mid-session (review finding 3)

Codex 0.164.0, on the scratch repo the last Codex run left behind:
- **A sandboxed agent cannot touch it.** In `codex sandbox -c sandbox_mode=workspace-write`, `touch` and `rm` in `.codex/` fail with `Operation not permitted`. In `src/` they work.
- **Codex keeps the hooks it loaded.** `.codex/hooks.json` was deleted from outside after session 01a17cb8 started. Codex still ran the Stop hook, and Codehere reported the file: settings reported `.codex/hooks.json`, 2 send-backs.
- **The agent version of this did not run.** Asked to `rm .codex/hooks.json` itself, the local model never ran the command. So that case was not observed.

- A real Claude Code agent's shell (this build session) ran `(sleep 1; printf 'y\r'; sleep 1) | script -q /dev/null codehere approve` in a scratch repo. Codehere answered `codehere approve asks you to confirm in your own terminal, not through an agent.`, and nothing was approved.
- `codex sandbox -- bash -c "… | script -q /dev/null codehere approve"` gave the same refusal, because `ps` is blocked there.

## Review (26 Oct)

Codex is out of usage until 17 Nov 2026. A code reviewer agent with no build notes read the diff, the spec and the vendor docs, ran `npm test` and its own scripts, and found 11 issues:

1. **High.** An agent that fakes a terminal could run `uninstall`. That deleted the session state, and `.codehere/` with it, so the finish check said nothing.
   - Checking this showed that Codex can give a command a terminal, so the terminal check behind `approve` stopped nothing on Codex.
   - Fixed in two layers. `approve` and `uninstall` refuse when an agent process is above them or the parents cannot be read. An uninstall that still gets through leaves a note outside the repo, which the open session's finish check reports.
2. **Medium.** `uninstall` walks up from the current folder and could act on the home folder. It now refuses there and outside git, and it names the folder before asking.
3. **Medium.** Nobody had checked whether Codex still runs the Stop hook after `.codex/hooks.json` changes mid-session. It does, and the sandbox blocks the agent from changing the file anyway. See above.
4. **Medium.** The README matrix was missing. It has been written.
5. to 9. **Low.** All fixed:
   - `--agent=codex` was not parsed;
   - a bare `--agent` was taken as Claude Code;
   - `constructor` and `__proto__` were accepted as agents;
   - the `.gitignore` line was removed although `.codehere/` was kept;
   - an edited `rules.md` with no `- ` lines was deleted;
   - a null hook entry crashed `uninstall`.
10. **Low.** Conformance script. Fixed:
    - it exited 0 when every check was BLOCKED;
    - a run overwrote a same-day result for another model;
    - L1 did not check "at the start";
    - the app-server calls had no timeout;
    - Claude's allowed tools were broader than needed.
11. **Low.** Test gaps. Covered by the tests above.
